# タグ送信点検 — 外部送信規律の公表事項チェック

![タグ送信点検 — 外部送信規律の公表事項チェック](https://getreadystack.com/img/promo/sku159673_result_card.jpg)

AIが書いたコードがこの規定を守っているか、という問いがいちばん先に刺さるのがここです。生成AIに「日本のサイトにGA4を入れるときの法対応は？」と聞くと、多くの場合GDPR風のCookie同意バナーが返ってきます。日本の外部送信規律（電気通信事業法27条の12・2023年6月16日施行）は同意ではなく **通知または公表** が原則で、求められるのはタグごとの公表4項目です。この食い違いが、納品後の手戻りになります。

この拡張は、開いているHTMLのソース全文から外部送信タグを探し、そのページの「人が読める本文」に書かれた公表事項と突き合わせ、足りないものを行番号つきで返します。

## 何を見るか（15 checks）

| 種類 | 数 | 中身 |
|---|---|---|
| 送信タグ検出 | 6 | GA4 / Meta ピクセル / LINE Tag / Yahoo!広告 / X広告 / 行動ログ計測(Clarity・Hotjar) |
| 公表4項目 | 4 | ①送信される情報の内容 ②送信先の名称 ③利用目的 ④オプトアウト（送信の停止）の方法 |
| 運用の穴 | 5 | 公表への導線なし / 同意バナーだけで公表なし / GTMコンテナ名だけの記載 / オプトアウト手順なし / 最終更新日なし |

判定の作法がひとつあります。**検出はHTMLソース全文、公表の有無は本文だけ**を見ます。`connect.facebook.net` というscriptのURLが書いてあることを「Metaピクセルを公表した」と数えないためです。本文の判定では `<script>` ブロックとHTMLコメント、タグの属性を落としてから探します。

## 同梱の見本で測った結果

- `_fixtures/dirty.html` … 54行の採用サイト。外部送信タグ4本（GA4・Meta ピクセル・LINE Tag・Yahoo!広告）とGTMコンテナ1つ。**6件**（L18 GTMコンテナのみ記載 / L24 Meta ピクセル未記載 / L31 LINE Tag未記載 / L36 Yahoo!広告未記載 / L43 公表4項目の④が無い / L43 最終更新日が無い）
- `_fixtures/clean.html` … 同じサイトを直したもの（最終更新日: 2026-09-14）。**0件**

## 使い方

1. HTMLファイルを開く
2. コマンドパレット → `外部送信規律: このファイルを点検`
3. 結果パネルに `行番号 / 規則ID / 直し方` が出ます

ブラウザ版（`index.html`）は同じ `ext/engine.js` を読み込んで動く、説明ページではない実物です。HTMLを貼れば同じ15 checksが走ります。
