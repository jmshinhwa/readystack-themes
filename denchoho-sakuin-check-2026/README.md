# 電帳法 索引簿チェック 2026 — 電子取引データの検索要件

電子取引データ（メール添付の請求書、ウェブ明細、EDI）の保存に使う **索引簿** を、
開いたその場で1行ずつ検査します。見るのは「あとで検索できるか」の一点です。

## なぜ索引簿を検査するのか

電子帳簿保存法第7条により、所得税・法人税の保存義務者は電子取引の取引情報を
電磁的記録のまま保存します（2024年1月1日以後は書面に出力して代える方法が使えません）。
保存の可視性の要件として、**取引年月日・取引金額・取引先** の3項目で検索できる状態が求められます。
国税庁が示す実務上の方法のひとつが、ファイル名をこの3項目で統一する方法と、
表計算ソフトで索引簿を作る方法です。索引簿を選んだ場合、検索できるかどうかは
索引簿の**書き方**で決まります。和暦が1行混ざる、金額に「¥」とカンマが入る、
取引先が「同上」になる——この3つだけで、その行は期間検索にも金額検索にも掛かりません。

基準期間（個人事業者は前々年、法人は前々事業年度）の売上高が5,000万円以下で、
ダウンロードの求めに応じることができる場合は、検索要件そのものが不要になります。
この判定は「前々年」を見るため、2024年に5,000万円を超えた個人事業者は
**2026年分から検索要件が必要** です。2026年分の取引は今まさに保存されています。

## 検査する12のルール（ext/rules.json）

| ルールID | 見るところ |
| --- | --- |
| date_wareki / date_not_iso / date_future | 取引年月日が西暦 YYYY-MM-DD か、未来日でないか |
| amount_mark / amount_not_number | 取引金額が半角数字（税込）だけか |
| partner_empty | 取引先が空欄・「同上」「〃」でないか |
| filename_empty / filename_char / filename_dup | ファイル名が空でなく、全角スペースや `\ / : * ? " < > |` を含まず、重複していないか |
| seq_number | 連番の重複・欠番 |
| no_jimushori_kitei | 「訂正削除防止の事務処理規程」への言及があるか（真実性の確保） |
| no_download_pledge | 「ダウンロードの求めに応じる」旨の記載があるか |

同梱の `_fixtures/clean.md`（12行）は0件、`_fixtures/dirty.md`（12行）は
**6行・7件**（うち1件は文書全体）を指摘します。数字はこの2つのファイルで実測したものです。

## 使い方

1. 索引簿の Markdown ファイル（`**/*.md`）を開く
2. コマンドパレットから `電帳法 索引簿チェック: このファイルを検査` を実行
3. 問題のある行に波線が出ます。`検査レポートを書き出す` で REPORT.md を作れます

エンジン（`ext/engine.js` と `ext/rules.json`）は拡張と無料ウェブ版で同一です。
どちらもファイルを外部に送信しません。すべてローカルで動きます。
